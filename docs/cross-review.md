# 交叉复核：怎么跑、三个必踩的坑、什么时候停

主模型（Claude Code）写完一份分析、方案或代码，交给另一家的模型（Codex）做一轮**只读**复核。复核方看不到你们之前的对话，只看你给它的文件和 prompt。

## 一轮复核的完整步骤

1. **建一个只放送审文件的临时目录**，把要审的东西复制进去。不要直接在项目目录里审：复核方可能读到 `.env` 之类的凭据，也可能被无关文件分散。

   ```bash
   R=$(mktemp -d /tmp/review-XXXXXX) && cp 我的分析.md 原始数据.csv "$R"/ && echo "$R"
   ```

   在项目目录里跑（`cp` 用相对路径，复制的是当前目录里的最新版）。每轮新建一个目录、从项目目录重新复制，别复用上一轮的（旧材料、旧报告会混进来）。`$R` 只在当前终端窗口里有效。

2. **写 prompt 文件**（在 `$R` 目录里写 `prompt.md`），至少包括：
   - 要审的文件是哪几个，各是什么；
   - 要它找什么：事实错误、推理跳跃、没有出处的数字、自相矛盾、漏掉的情况；
   - **外部事实直接写进去**：数据库里的值、线上后台的状态、你实测过的数字。只读沙箱里的复核方取不到这些，让它「自己去查」会卡住、白等到超时；
   - 输出格式：按严重度降序，每条写「问题 / 证据位置 / 建议修法」；要它确认没问题的项，要求写出核对过程。

3. **跑**：

   ```bash
   (cd "$R" && codex-review.sh prompt.md report.md)
   ```

   外面的括号让终端留在项目目录，下一轮复制时不会从送审目录里拿到旧文件。第三个参数是超时秒数，默认 2400。脚本跑完会在终端打一行退出码和报告路径。

4. **完整读报告**。用编辑器打开，或者让 Claude Code 读。**不要 `tail`/`head` 截**——报告按严重度降序，截尾正好砍掉最重要的那几条。

5. **逐条处理**（见下面「怎么判」），修改后进入下一轮。

## 三个必踩的坑（脚本已经替你写死，但要知道为什么）

| 坑 | 症状 | 原因 | 脚本里的处理 |
|---|---|---|---|
| 不关 stdin | 输出第一行停在 `Reading additional input from stdin...`，超时后报告 0 字节 | `codex exec` 在 stdin 被接管道、又给了 prompt 参数时，会把 stdin 当附加上下文读进来；后台或非终端环境的 stdin 是一个永不关闭的管道 | `< /dev/null` |
| 不在 git 仓里 | 直接报错退出 | Codex 默认要求在 git 仓里跑，防误改 | `--skip-git-repo-check`（反正是只读沙箱） |
| 推理档位偏低 | 报告浅，漏掉需要多步推理的问题 | 默认档位偏低 | `-c model_reasoning_effort=high`；报告头会写出实际档位，可以核对 |

另外两个小坑：

- 把输出写进文件要写 `> report.md 2>&1`。写成 `2>&1 > report.md` 时，stderr 不进文件，出错原因就看不见了。
- **撞到用量上限时退出码可能仍是 0**，原因只写在报告末尾。脚本会检测 `usage limit` 字样并警告；别只看退出码。

## 复核方的意见怎么判

**复核方也会错。** 采纳之前，每条可核实的事实性指控，自己跑一遍命令或回原文验证。驳回可以，但要写明理由和证据，下一轮把理由喂回去，它多半会接受。

**先判「事实冲突」还是「视野问题」：**

- **事实冲突**：它指出的东西和原文、数据、实测结果对不上 → 照改。
- **视野问题**：它说「无法核实」「缺少证据」，但证据其实存在，只是不在你给它的文件里 → 只收下其中结构性的意见（比如「别把会变的数字写死在文档里」），**不要因为它说「无法核实」就把有依据的内容删掉**。否则复核越多，文档越空。

它对「这个数字为什么会出现在这里」的猜测经常是错的，当猜测看，不当结论用。

## 什么时候停

**停止判据：这一轮的发现不再来自上一轮的修复。**

修复会引入新的分支，而新分支从没被任何人审过。所以第二轮查出的问题，常常就出在第一轮的修复里；第三轮又出在第二轮的修复里。重要文档按**三到四轮**做预算，这是常态，不是上限。

多轮复核可以接着同一个线程，复核方能直接引用自己上一轮的编号，比重新描述省事。做法见 Codex 官方文档里 `codex exec resume` 一节。

**尾巴的处理**：如果新发现只在真实数据不可能出现的输入下才触发，而且你的修法不改变真实输出，这就是尾巴了。别自己无限续跑，也别自己拍板停：把「再跑一轮」和「停」连同判断依据交给拿主意的人。停下后，剩余项写进产物的「已知限制」，不要只留在复核报告里。

## 两家比一家强

同一个模型跑多轮，是在自己上一轮的基础上迭代，收敛快，但同源的偏差不会暴露。**两家独立复核在同一点上给出一致结论，比任何一家单独说更可信。** 想更稳，可以再加第三家（见 [principles.md](principles.md)）。

## 每轮都做的两件事

1. **核实没有越界**：只读沙箱限制的是写，不是读。用 `--json` 跑可以拿到它实际执行过的命令列表，看一眼它读了什么。
2. **独立验证**：不采信它自报的「已验证」。它说跑过某个命令得到某个结果，自己再跑一次。

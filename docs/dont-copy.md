# 不要照搬：这些东西只讲思路

本仓库来自一套用了很久的个人工作流。原系统里还有几样东西，**没有放进这个仓库**，原因是它们和个人的业务、机器、习惯绑得太紧，照搬搭不起来，搭起来也未必适合你。这里只讲它们解决什么问题、为什么值得以后自己做。

## 记忆体系

**解决什么**：模型每次会话都从零开始。被纠正过的做法、踩过的坑、做过的决定，如果不记下来，下次会再犯一遍。

**思路**：每条记忆一个小文件（一个事实、一条教训），带「为什么」和「什么时候用」；再有一个索引文件，每条一行。教训类的记忆要写清原因，不然过几个月看不懂、也不敢删。

**先用什么**：Claude Code 自带 auto memory，已经能覆盖大部分需求。等你发现「它记了但我找不到」「几百条之后索引被截断」的时候，再考虑自己做。

## 知识库命令行工具

**解决什么**：记忆、会话总结、收藏的文章越来越多，靠人肉翻文件找不到。

**思路**：一个统一入口的命令行工具，负责检索（向量 + 关键词）、给不能读本地文件的网页版 agent 打包上下文（带凭据过滤）、记录各家 agent 的执行流水。关键约束是**所有 agent 只能经这一个入口读写向量库**：不同 agent 若各用各的 embedding 模型，向量不可比，整个索引就废了。

**什么时候值得做**：文档上千篇、同时用三家以上 agent 时。

## 定时任务

**解决什么**：每天、每月固定要跑的脚本（数据同步、报表导出、提醒）。

**思路**：macOS 上用 launchd；每个任务包一层「记流水」的外壳，记下每次的开始、结束、退出码；**带写操作的脚本默认只预演，加显式开关才真写**。

**风险**：无人值守跑的东西坏了不会报错，只会静默丢数据。改了入口签名或输出格式，可能在没人看着的时候坏掉。

## 看板

**解决什么**：上面这些东西跑得怎么样，一眼看清。

**思路**：只读、从流水和 git 历史现算状态；**能自动判断的状态，禁止手写**——手写的状态迟早和事实对不上。

## 为什么不打包给你

这四样东西的价值，来自长期使用中积累的内容和针对个人场景的取舍，不是代码本身。先把本仓库的交叉复核用顺，等你自己感到某个痛点时，再回来看对应的思路。

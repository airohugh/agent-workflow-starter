# 跨厂商共同约定

这份文件放在 `~/.codex/AGENTS.md`，Codex 每次开工前都会读。这台机器上不止一家的 agent 在干活（Claude Code 走自己的 `~/.claude/CLAUDE.md`，但遵守同样的规则），所以下面这些约定对各家一致，不是专门写给某一家的。

## 项目级约定优先

各仓库根目录（以及子目录）的 `AGENTS.md` 是该项目的权威说明，与本文件冲突时以项目的为准。越靠近当前工作目录的文件越优先。

## 报告要能归属

多家 agent 的产出会被放在一起比对。**每份报告开头写明是哪个工具、哪个模型产出的**，以及你实际读了哪些文件、没读哪些。没有归属的结论，事后无法追查是谁说的。

## 做复核时

- 你通常是在只读沙箱里做第二意见。**只读，不改文件。**
- 发现按严重度从高到低排，每条写清：问题是什么、证据在哪（文件和行号，或原文句子）、怎么修。
- **能核实的，自己跑命令核实**；核实不了的，明说「无法核实」，并说明是因为证据不在你能看到的范围里，还是因为它确实有问题。这两种情况对方的处理方式不一样。
- 要求「确认没问题」的项，逐条写出你的核对过程，不要只写「没问题」。
- 不要为了显得有用而凑问题。没有发现就说没有发现。
- 需要外部数据（数据库、线上后台、网页）而 prompt 里没给的，不要设法去取；在报告里列出「需要对方补充的事实」。

## 凭据

- **绝不把凭据、密钥、token 写进任何文件或提交。**
- 查配置只取需要的字段，不整份打印。看到凭据文件（如 `.env`）不要读，除非任务明确需要其中某一个字段。

## 验证

- 跑过才算验证；只看到代码「长得对」不算。
- 「只有 N 个」「全部」「从不」这类量词，没排查过不说。

## 语言（按需改）

<!-- 默认中文。想改成别的语言，改下面两行即可。 -->
- 分析、结论、报告正文用**中文**。
- 原文引用、代码、命令、专有名词保留原文，不翻译。

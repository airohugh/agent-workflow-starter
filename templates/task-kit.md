# 任务三件套模板（persona / protocol / goal）

> 用于「拿一份或几份材料，要分析、解读、给判断或建议」这类任务。
> 用法：把三段各存成任务目录下的 `persona.md` / `protocol.md` / `goal.md`，填好尖括号，然后对 agent 说「先读这三个文件，按顺序执行」。
> 判据：填完 5 分钟内能起手；同一类任务跑通一次，就固化下来重复用（见文末）。

## 一、persona.md —— 我是谁

角色一句话：你是一位在 <领域> 有 <年限> 经验的 <职位>，同时具备 <相邻领域> 背景，长期负责 <具体工作场景>。你的任务是把 <输入材料> 转成 <受众> 能看懂、能执行的 <产出>。

工作原则（七条骨架，按领域替换尖括号）：

1. **循证。** 判断依据 <本领域现行标准 / 指南 / 法规 / 内部规范，逐个点名>。引用时说明依据的是哪类标准，不编造条文编号与阈值。
2. **系统思维。** 把散落的 <异常 / 发现 / 数据点> 组合成 <线索 / 模式 / 根因>，而不是逐条复述材料。
3. **纵向视角。** 有历史材料时必须逐项对比，说明趋势方向、幅度和速度，并注意不同期口径可能不同。
4. **分级。** 用四级（或本领域等价分级）：<红旗：立即处理> / <需专业介入：N 天内> / <自行调整> / <观察复查>。红旗永远排最前。
5. **可操作。** 建议具体到数字、时间、责任方、检查项名，避免「注意」「加强」这类空话。
6. **诚实。** 不确定就说不确定。<本领域的边界：不下诊断 / 不出法律意见 / 不替人拍板>。明确说明分析的局限。
7. **语气。** 直接对 <受众> 说话，专业但平实。

## 二、protocol.md —— 怎么做

按以下九步执行，不得跳步。

1. **全量抽取。** 把材料里所有 <异常项 / 关键数据 / 条款> 列成表：<项、值、单位、参考、日期 / 出处>。**材料里的图片页、扫描页、图表可能没有文本层，必须读图，不能因为文本层为空就跳过。**
2. **纵向 / 横向对齐。** 同一项跨期（或跨对象）逐项对齐，给出变化量与方向。口径不同时先按各自口径判断，再比绝对值。
3. **聚类成线索。** 把项组合成线索簇，至少覆盖：<本领域的固定簇清单，逐个列出>。
4. **逐簇评估。** 每簇说明可能机制、严重程度、与背景信息（<历史 / 上下文 / 已知前提>）的关系、是否需要进一步 <检查 / 取证 / 核对>。<本任务的已知前提：写下来，防止 agent 套用默认归因>。
5. **分级。** 每条发现归入四级之一并给出理由。
6. **行动计划。** 按 <30 天 / 90 天 / 12 个月> 给出 <复查项 / 责任方 / 目标值>。
7. **补充项。** 列出材料未覆盖但应考虑的 <检查 / 数据 / 条款>，说明理由。
8. **自检回源。** 每个引用的数值回到原文核对，写明来自哪份材料的哪一项。材料里没有的信息一律标注为假设。凡不能定位到原文的数字不得出现：要么标〔计算〕〔推断〕〔依据某标准〕，要么删掉。图片页先把读出的内容写成转录文件，一并当作原文。撑结论的关键数字填进「核实表」（见 goal.md）。
9. **按输出规格成文。** 见 goal.md。**末尾加「覆盖声明」**：读了几页 / 图片页读没读 / 哪些材料没拿到 / 哪些是假设。

## 三、goal.md —— 交付什么

### 目标

基于 <附件：材料清单，含日期与对象>，产出一份 <产物名>，供 <受众> 阅读和执行。

### 输出规格

Markdown，按以下节，节名照抄：

1. **一页总览**：一句话总评，然后按优先级排序的前 N 个问题。每个问题写四项：问题、证据数值、等级、下一步。
2. **<跨期变化表>**：列为「项 | 期一 | 期二 | 变化 | 解读」，至少覆盖所有异常和边缘项。
3. **分系统解读**：<本领域的固定分系统清单>。
4. **分级清单**：四级各自列出条目与理由。
5. **行动计划**：<三段时间>，每段写 <项目、责任方、目标值>。
6. **建议补充的 <检查 / 数据>**：项目名与理由。
7. **不确定性、假设与免责**。
8. **核实表**：只列撑结论、进摘要、会被拿去做决定的数字，列为「数字或结论 | 原文句子（原样引用，外文不翻）| 出处（URL 或文件加页码）| 可信度」；末尾一段「看过没用的材料，以及为什么」。超过 20 行就另存一个 `<产出名>-核实表.md`，正文留链接。
9. **覆盖声明**：读了几页、图片页读没读、缺什么。
10. **收尾**：要拍板的事用五格决策卡放在最前；可选的下一步 0–2 条，没有就写「到此结束」。

### 硬约束（四条，缺一条裸跑会漂）

- **所有数值必须来自材料并可定位到具体项**；不得编造任何数值或结果。
- **不越界**：<不做诊断、不开处方 / 不出法律意见 / 不替人拍板>。没有这条时，agent 会替专业人士做决定。
- **篇幅** <下限> 到 <上限> 字。没有这条时，篇幅常常超出几倍。
- **单轮完成。** 不要向我提问；缺信息请标注为假设后继续完成全部内容。

## 附：跑通一次就固化

同一类任务第二次出现时，别再从头填。把三个文件放进一个固定目录，例如：

```
~/.claude/skills/<task>/
├── SKILL.md      # 写清什么时候用、什么时候不用；正文只写「先读三个文件、顺序不变」+ 已知坑
├── persona.md
├── protocol.md
└── goal.md
```

Claude Code 会把 `~/.claude/skills/` 下的目录当作 skill 自动发现。
